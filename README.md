# IPTV / HLS restream proxy

Асинхронный HTTP-прокси на `aiohttp`, полностью ретранслирующий HLS-плейлисты
и все связанные ресурсы (сегменты `.ts`/`.m4s`, вложенные вариант-плейлисты,
ключи шифрования) через себя, переписывая все ссылки на свой адрес. Клиент
никогда не обращается к серверу провайдера напрямую. Управление
пользователями не реализуется — доступ открыт всем, кто знает адрес прокси;
веб-интерфейс управления провайдерами (`/admin/`) закрыт одним общим паролем
и без него выключен (см. "Провайдеры (каналы)").

## Конфигурация

Деплой-параметры — в `config.py`:

```python
port = 1200
host_name = 'mydomain.com'
```

| Параметр | Назначение |
|---|---|
| `port` | Порт сервера. Переопределяется `IPTV_PROXY_PORT` из `.env`. |
| `host_name` | Домен/IP, который клиенты используют для обращения к прокси — подставляется во все переписанные ссылки. Переопределяется `IPTV_PROXY_HOST_NAME` из `.env`. |
| `scheme` | `http`/`https` — схема в переписанных ссылках (если прокси стоит за nginx с SSL-терминацией, ставьте `https`, сам сервер всё равно слушает обычный HTTP). |
| `user_agent`, `connect_timeout`, `read_timeout` | Опциональны, есть разумные значения по умолчанию. |
| `trust_x_forwarded_for` | `True` — брать IP клиента из `X-Forwarded-For` (для блокировки перебора пароля `/admin/`). Включать, только если прокси доступен исключительно через nginx. По умолчанию `False`. |
| `provider` | Используется **только один раз**, при самом первом запуске, как начальные данные для `data/providers.json` — дальше провайдеры не отсюда, см. ниже. |

Порт и `host_name` вынесены в `.env` намеренно как единый источник истины:
значение из `.env` используется сразу и для bind-порта сервера, и для
ссылок, отдаваемых клиентам, и для `ports:`/`environment:` в
`docker-compose.yml` — так исключается ситуация, когда наружу опубликован
один порт/домен, а в плейлисте зашит другой. Если переменная не задана,
используется значение из `config.py`.

### Провайдеры (каналы)

Список провайдеров хранится не в `config.py`, а в `data/providers.json` и
управляется через `http://<host_name>:<port>/admin/`: таблица текущих
провайдеров (ключ, URL, доп. заголовки) со ссылками "Изменить"/"Удалить" и
форма добавления (ключ, URL плейлиста, опционально заголовки вида
`Имя: значение` — например `Referer`, если провайдер его проверяет).
Изменения через `/admin/` применяются сразу, без перезапуска.
`data/providers.json` можно также редактировать вручную — такие правки
применяются после перезапуска контейнера.

При самом первом запуске, если `data/providers.json` ещё не существует, он
автоматически заполняется из `provider = {...}` в `config.py`.

**Пароль на `/admin/`.** `/admin/` работает только при заданном
`ADMIN_PASSWORD` в `.env` (и опционально `ADMIN_USER`, по умолчанию
`admin`) — без системы пользователей, один общий логин/пароль:

```
ADMIN_USER=admin
ADMIN_PASSWORD=укажите-свой-пароль
```

Если `ADMIN_PASSWORD` пуст/не задан — `/admin/` **выключен** и отвечает
`404` (в лог при старте выводится предупреждение).

Это HTTP Basic Auth — браузер сам покажет системное окно логина при заходе
на `/admin/*`; сами плейлисты/каналы авторизации не требуют. Дополнительно:

- **Перебор пароля:** после 10 неверных попыток за 10 минут с одного IP
  этот IP получает `429` на 15 минут (даже с верным паролем). Если прокси
  стоит за nginx, все клиенты видны с IP nginx — включите
  `trust_x_forwarded_for = True` в `config.py` (и закройте прямой доступ к
  порту прокси), иначе при переборе вход блокируется для всех.
- **CSRF:** изменения (POST) принимаются только со страниц самого прокси
  (проверка `Origin`/`Referer`) — чужой сайт не может от имени залогиненного
  администратора удалить или подменить провайдера.
- **Лог:** неверные логины, блокировки, отклонённые POST с чужих сайтов и
  все добавления/изменения/удаления провайдеров пишутся в лог как
  `WARNING` с префиксом `Админка:` (IP, `X-Forwarded-For`, User-Agent):
  `docker logs -f iptv-proxy 2>&1 | grep 'Админка:'`.
- **HTTPS:** Basic Auth передаёт пароль фактически открытым текстом
  (base64). Если админкой пользуются не только из локальной сети — ставьте
  прокси за nginx с TLS и заходите в `/admin/` только по `https://`.

### Подпись ссылок

Все ссылки на ресурсы, которые прокси вписывает в плейлисты
(`/<ключ>/res/<подпись>/<токен>`), подписаны HMAC от пары (ключ провайдера,
исходный URL). Ссылки с неверной подписью отклоняются с `403` — так прокси
нельзя заставить скачать произвольный URL (в т.ч. из внутренней сети) или
отправить заголовки провайдера на чужой хост.

Секрет подписи генерируется при первом старте в `data/secret.key`. Его нельзя
удалять или терять: при смене секрета все ранее выданные ссылки (в т.ч.
закэшированные IPTV-приложениями списки каналов) перестанут работать, пока
плейлист в приложении не будет перезагружен. По той же причине после
обновления на версию с подписью плейлисты в приложениях нужно один раз
обновить.

## Запуск через Docker

```bash
cp .env.example .env   # поменять IPTV_PROXY_PORT / IPTV_PROXY_HOST_NAME / ADMIN_PASSWORD
docker compose up -d --build
```

- `config.py` в образ не встраивается — монтируется как read-only volume,
  правка + `docker compose restart iptv-proxy` без пересборки.
- `data/` (там лежит `providers.json`) монтируется read-write — провайдеры,
  добавленные через `/admin/`, сохраняются на хосте и переживают рестарт.
- После изменений в коде (`server.py`, `providers_store.py`,
  `requirements.txt`, `Dockerfile`) — пересборка образа:
  ```bash
  docker compose up -d --build
  ```
  Если после пересборки кажется, что код не обновился — форсировать без
  кэша:
  ```bash
  docker compose build --no-cache && docker compose up -d
  ```

После запуска:
- `http://<host_name>:<port>/<ключ>/` — плейлист провайдера.
- `http://<host_name>:<port>/admin/` — управление провайдерами.
